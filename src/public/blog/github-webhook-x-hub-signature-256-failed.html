GitHub Webhooks: X-Hub-Signature-256 Verification & Why Failed Deliveries Aren't Retried

Developers used to Stripe or Shopify often assume every webhook provider retries automatically after a transient 502 Bad Gateway. GitHub is different — and that surprise quietly breaks release pipelines, PR bots, and deployment triggers.

1. Two Critical GitHub Webhook Constraints

  • No automatic retries: Unlike billing providers with exponential backoff queues, GitHub does not automatically redeliver failed webhook deliveries. If your service restarts right when a push or pull_request event fires, that event stays failed unless someone manually clicks Redeliver (or invokes the Redeliver REST endpoint) before logs age out after 3 days (72 hours).
  • 10-second timeout budget: GitHub aborts waiting if your endpoint takes more than 10 seconds to return an HTTP 2xx status. Running synchronous builds, container pulls, or LLM PR reviews before returning 200 OK guarantees timeout errors.

2. Fixing X-Hub-Signature-256 Verification in Node.js

GitHub sends two signature headers for backwards compatibility (X-Hub-Signature SHA-1 and X-Hub-Signature-256 SHA-256). Always validate X-Hub-Signature-256 against the unparsed raw request bytes using a constant-time comparison:

const crypto = require('crypto');

function verifyGitHubSignature(rawBody, sig256Header, secret) {
  if (!sig256Header) return false;

  const expected = 'sha256=' + crypto
    .createHmac('sha256', secret)
    .update(rawBody) // raw Buffer from express.raw() or req.text()
    .digest('hex');

  const a = Buffer.from(expected, 'utf8');
  const b = Buffer.from(sig256Header, 'utf8');
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}

Common Causes of Signature Mismatches

  • Content-Type set to application/x-www-form-urlencoded: If you left GitHub's webhook content type at form-urlencoded instead of application/json, your JSON middleware ignores the body or wraps it inside req.body.payload, breaking raw-byte HMAC checks.
  • Body parser mutation: Calling express.json() globally before your webhook route discards the raw byte stream.
  • Missing sha256= prefix or wrong casing: Remember HTTP headers are normalized lowercase in Node (req.headers['x-hub-signature-256']), and the digest must keep the sha256= prefix before comparison.
