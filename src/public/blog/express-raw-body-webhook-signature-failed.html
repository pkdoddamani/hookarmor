Fix "No Signatures Found Matching the Expected Signature" in Express.js Webhooks

Almost every Express backend hits this error the first time Stripe, Shopify, Clerk, or GitHub calls production:

StripeSignatureVerificationError: No signatures found matching the expected signature for payload. Are you passing the raw request body you received from Stripe?

Even when your webhook signing secret (whsec_...) is copied verbatim, the cryptographic digest mismatches by a few invisible whitespace characters because Express already parsed and rebuilt the JSON.

1. Fix Option A: Mount express.raw() Before express.json()

Express evaluates middleware strictly from top to bottom. Put your raw-body webhook route above app.use(express.json()) so the webhook stream stays an untouched Buffer:

const express = require('express');
const stripe = require('stripe')(process.env.STRIPE_SECRET_KEY);
const app = express();

// 1. Mount raw Buffer parser FIRST on webhook path
app.post('/webhooks/stripe', express.raw({ type: 'application/json' }), (req, res) => {
  const sig = req.headers['stripe-signature'];
  const event = stripe.webhooks.constructEvent(
    req.body, // exact Buffer bytes
    sig,
    process.env.STRIPE_WEBHOOK_SECRET
  );
  res.json({ received: true });
});

// 2. Normal JSON parsing AFTER webhook routes
app.use(express.json());
Don't forget routers & Reverse Proxies: Mounting app.use(express.json()) inside app.js and then registering webhook routes later inside an imported router still runs express.json() first! Also beware of Nginx/Cloudflare rules rewriting HTTP to HTTPS or trailing slashes (`301`/`308` redirects strip/drop signed POST deliveries).

2. Fix Option B: Capture rawBody via verify Hook

If global express.json() middleware is unavoidable across legacy routers, preserve the raw buffer directly inside Express's built-in verify option:

app.use(express.json({
  verify: (req, res, buf) => {
    if (req.originalUrl.startsWith('/webhooks')) {
      req.rawBody = buf;
    }
  }
}));

app.post('/webhooks/shopify', (req, res) => {
  // Verify X-Shopify-Hmac-Sha256 using req.rawBody (Buffer), never req.body
  res.sendStatus(200);
});

3. Why Raw Body Parsing Is Only Half the Battle

Once your Express endpoint verifies raw signatures properly, the next production surprise happens during database lockups, deploy restarts, or bug fixes: valid signed events fail downstream with HTTP 500, get lost if unbuffered (like GitHub), or fail constructEvent() upon delayed replay when Stripe's 300-second timestamp tolerance expires.
