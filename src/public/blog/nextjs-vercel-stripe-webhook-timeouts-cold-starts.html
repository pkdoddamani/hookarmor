Fixing Next.js & Stripe Webhook 502/504 Timeouts on Serverless Deploys

You ship a Next.js App Router SaaS with Stripe Checkout, wire up app/api/webhooks/stripe/route.ts, test it cleanly with the Stripe CLI, and launch. Then two weeks later a customer emails asking why their card was charged while their account still shows Free Plan.

When you open the Stripe Dashboard, the delivery log shows 504 Gateway Timeout or 502 Bad Gateway followed by Stripe backing off over hours — or worse, your own replay failing signature checks.

1. Why Bumping Serverless maxDuration Does Not Fix It

Even on hosts with generous default serverless timeouts (such as Vercel's Fluid Compute 300s default), the webhook sender hangs up first:

  • Stripe waits briefly and treats slow responses as failed attempts, switching to exponential backoff for up to 3 days (72 hours) in live mode (and only 3 retries in test mode).
  • Shopify cuts off at 5 seconds and deletes API webhook subscriptions after 8 failures in 4 hours.
  • During Stripe's exponential backoff, retry gaps stretch into hours. Your customer gets redirected back from Stripe Checkout right away, sees no active plan, and opens a chargeback.

2. The 4 Real Causes of Dropped Next.js Webhooks

1) Cold Starts & Deploy Restarts

A 15-second container swap on Render/Fly.io or a serverless cold start loading heavy ORMs right as checkout.session.completed arrives returns 502 or stalls past the provider timeout.

2) Monthly Billing Burst Exhausting Postgres Connections

On the first of the month, 150 invoice.payment_succeeded webhooks arrive within seconds. Serverless instances spin up concurrently, each opens new Postgres/Prisma connections, connection pools saturate, and half the requests crash with HTTP 500.

3) Domain Redirects Stripping POST Signatures (307/308)

Registering https://example.com/api/webhooks/stripe when your Next.js app redirects to https://www.example.com/... causes Stripe and Shopify to treat the redirect as a webhook failure. Always inspect exact DNS canonical hosts.

4) Mutating the Request Body Before constructEvent()

In Next.js App Router, reading raw text before parsing JSON preserves exact HMAC bytes:

import { headers } from 'next/headers';
import { NextResponse } from 'next/server';
import Stripe from 'stripe';

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);

export async function POST(req: Request) {
  const rawBody = await req.text();
  const signature = (await headers()).get('stripe-signature') ?? '';

  const event = stripe.webhooks.constructEvent(
    rawBody,
    signature,
    process.env.STRIPE_WEBHOOK_SECRET!
  );

  // Your billing update...
  return NextResponse.json({ received: true });
}
