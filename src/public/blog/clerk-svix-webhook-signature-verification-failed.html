Fixing Clerk & Svix Webhook Signature Verification Errors (And Replay Timeouts)

When a user signs up through Clerk, your backend depends on user.created and user.updated webhooks (delivered via Svix) to create a matching user row in Postgres or provision their workspace. If that single webhook fails verification or misses a database write during a deploy reboot, the user logs in and immediately hits broken foreign keys or a blank dashboard.

1. How Svix Signs Clerk Webhooks

Every request includes three headers:

  • svix-id: Unique message ID for idempotency tracking.
  • svix-timestamp: Unix seconds timestamp used for replay protection.
  • svix-signature: Space-separated list of Base64 signatures prefixed with version (for example, v1,g0hM9SsE...). During secret rotation, multiple v1,... entries can appear in the same header.

Under the hood, Svix computes the signature using three strict steps:

const crypto = require('crypto');

function verifySvixSignature(rawBody, headers, signingSecret, toleranceSec = 300) {
  const id = headers['svix-id'];
  const ts = headers['svix-timestamp'];
  const sigHeader = headers['svix-signature'];
  if (!id || !ts || !/^\d+$/.test(ts) || !sigHeader) return false;

  // 1. Enforce 5-minute replay tolerance window
  const now = Math.floor(Date.now() / 1000);
  if (Math.abs(now - parseInt(ts, 10)) > toleranceSec) return false;

  // 2. Strip "whsec_" and Base64-decode key bytes
  const secretBytes = Buffer.from(signingSecret.replace(/^whsec_/, ''), 'base64');

  // 3. Sign "${svix-id}.${svix-timestamp}.${rawBody}" and encode digest as Base64
  const hmac = crypto.createHmac('sha256', secretBytes);
  hmac.update(`${id}.${ts}.`);
  hmac.update(rawBody); // must be untouched raw Buffer/string bytes
  const expected = hmac.digest('base64');

  return sigHeader.split(' ').some((entry) => {
    const [version, sig] = entry.split(',');
    return version === 'v1' && sig &&
      sig.length === expected.length &&
      crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
  });
}

2. The 4 Mistakes That Trigger Verification Errors

Mistake 1: Passing the Raw whsec_... String to HMAC

Unlike Stripe hex HMAC keys or GitHub shared strings, Svix secrets encode raw key bytes in Base64 after the whsec_ prefix. Hashing with the ASCII characters whsec_... directly always fails.

Mistake 2: Re-Stringifying JSON After Parsing

If middleware parses JSON before your handler reads the payload, calling JSON.stringify(req.body) alters spacing or Unicode escaping and changes the digest of ${svix-id}.${svix-timestamp}.${rawBody}.

Mistake 3: Comparing Only the First Signature Token

When rotating webhook secrets or verifying multi-entry svix-signature headers, splitting once or only reading index [0] breaks valid deliveries mid-rotation.

Mistake 4: Replaying Buffered Failures Without Refreshing svix-timestamp

The 5-minute dead-letter wall: Svix enforces a 300-second tolerance window on svix-timestamp. If your app stores failed user.created payloads in a custom queue and replays them 20 minutes later with the original timestamp, the stock svix SDK rejects your own replay!
